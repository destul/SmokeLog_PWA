# SmokeLog 0.4 Design

## Goal

Make SmokeLog useful for a longer quit/reduction journey: show month, quarter,
and year analytics; support three interface languages; explain Safari PWA
installation; add reduction goals and achievements; and clearly separate real
measurements from projections.

## Scope

This release excludes VPS migration, custom domains, HTTPS, accounts, and
server synchronization. IndexedDB remains the source of truth and existing
backup data stays compatible.

## Approved behavior

- Forecast periods are 30, 90, and 365 days. A forecast is derived from the
  observed average daily cost/quantity/time and is labeled as a projection.
- Analytics use local calendar days and preserve the existing cigarette/stick
  unit and product-price rules.
- The user may select Ukrainian, Russian, or English. The selected language is
  stored locally and does not alter records.
- Safari help is a dismissible in-app instruction explaining Share → Add to
  Home Screen and the custom app name field.
- A reduction goal is a daily maximum unit count. The UI shows actual units,
  target, remaining/over-target state, and progress without deleting or
  rewriting events.
- Achievements are derived from stored events: longest pause, days at or under
  goal, money saved against the baseline, and time returned. No gamification
  data is persisted separately.
- Every analytics card distinguishes observed data from projected values.

## Technical approach

Keep pure calculations in domain modules and keep IndexedDB as persistence.
Extend the existing App screen and CSS with small reusable controls. Add
regression tests for calculations, settings persistence, language rendering,
forecast switching, goal states, achievements, and the Safari instruction.
