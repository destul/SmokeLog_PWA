# SmokeLog 0.2.1 — «Вижу зависимость» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the existing local-only consumption tracker into a factual awareness tool: exact quick product logging, craving/outcome tracking, personal time and cost projections, and product-specific health education.

**Architecture:** Keep the React single-page PWA and IndexedDB local-only. Extend the domain with craving events, product subtype metadata, forecast and health-insight pure functions; migrate IndexedDB from v1 to v2 without touching saved consumption events. App.tsx remains the composition root, while calculations and static educational copy live in focused domain modules and are tested without the UI.

**Tech Stack:** React 19, TypeScript, Vite 8, Vitest, Testing Library, fake-indexeddb, idb, vite-plugin-pwa.

**Spec:** `docs/superpowers/specs/2026-08-20-awareness-design.md`

## Global Constraints

- Release version is exactly `0.2.1`; pre-platform releases remain in `0.x.x`; `1.0.0` is reserved for the platform launch.
- UI copy remains Ukrainian in this release.
- All personal data stays in IndexedDB; do not add accounts, network APIs, analytics, or server persistence.
- Keep the existing `З останнього разу` counter as the only timer.
- Never present a diagnosis, individual risk percentage, recovered-health percentage, or lost-years calculation.
- Money and time forecasts use a completed seven-day personal observation window; monthly and quarterly projections use 30 and 90 days respectively.
- Cigarettes and IQOS sticks count as seven estimated minutes each; label all time output as an estimate.
- Health claims must be category-specific and contain source links; keep vape and snus education brief.
- Preserve import of version-1 JSON backups and do not delete local data during any import or schema upgrade.
- Out of scope: savings goals, push notifications, quit challenges, server migration, domains, cloud sync, and language switching.

- [ ] **Step 3: Implement pure, deterministic selectors**

```ts
export function recentQuickProducts(products: Product[], events: ConsumptionEvent[]): Product[] {
  const active = products.filter((product) => product.active)
  const byId = new Map(active.map((product) => [product.id, product]))
  const chosen: Product[] = []
  for (const event of [...events].sort((a, b) => b.occurredAt.localeCompare(a.occurredAt))) {
    const product = byId.get(event.productId)
    if (product && !chosen.some((item) => item.id === product.id)) chosen.push(product)
    if (chosen.length === 3) return chosen
  }
  return [...chosen, ...active.filter((product) => !chosen.some((item) => item.id === product.id))]
    .sort((a, b) => b.createdAt.localeCompare(a.createdAt))
    .slice(0, 3)
}
```

Put Ukrainian, factual title/body/sourceUrl health cards in `health.ts`; choose cigarette by default, use a dedicated stick card, brief vape card, tobacco snus card, and nicotine-pouch card.
